# Replace ManyChat With OpenReply Plus Claude

You can get ManyChat's core trick, where someone comments a keyword and gets a DM, without paying for ManyChat. Self-host an open-source tool on Meta's official Instagram API and you pay **roughly $0–5 a month for hosting plus a few dollars of Claude usage**, compared with ManyChat Pro's ~$29–39 plus Anthropic fees. The repo you most likely saw is **diwenne/openreply**. It has about 2,460 stars and 970 forks after ten weeks, and it went viral through a "comment 'open'" reel with **169,486 views and 8,801 comments**, with the DMs sent by OpenReply itself ([diwen.ca](https://www.diwen.ca/highlights/openreply)). It is MIT-licensed, uses only the official API and has no AI. A related fork, Xeven777/openinstadm, already uses Claude for DM replies, and ChatbotX and n8n are heavier options with Claude built in. The biggest finding is about approval. Meta's documentation and several repos' setup guides agree that automating **only your own professional account runs on Meta's default Standard Access, with no App Review and no Business Verification**. Two conditions apply: the Meta app must be switched to Live, and your account must accept a role on it. That conclusion comes from Meta's platform overview and developer guides, not from Meta's App Review page, and a few older platform docs suggest otherwise. Treat it as highly likely, and confirm it with a one-comment test before you build on it. The recommended path is to fork OpenReply, use Claude for the DM conversation rather than the keyword trigger, and avoid password-login "Instagram DM" tools. Those tools put the account at risk, and none of them offer comment-to-DM.

## OpenReply is the viral repo and leads its field threefold

OpenReply calls itself "Open-sourced ManyChat for Instagram comment-to-DM automation." When a comment matches a keyword, it sends the commenter a private reply "through the official Meta API." It can also post a public reply. The README says it "does not scrape, it does not automate a browser, and it never asks for an Instagram password" ([OpenReply README](https://github.com/diwenne/openreply)). Features include DM and Story-reply keyword triggers, up to two link buttons, a follow gate, `{username}` personalization, tracked links, multi-account workspaces, an inbox, and rate limiting under Meta's cap of **750 private replies per hour**. It is **self-hosted only**: the public site is a dashboard demo, not a service you can sign up for. It was launched on 2026-07-17, passed 1,000 stars in three weeks, and at least 18 other creators made unpaid videos about it ([diwen.ca](https://www.diwen.ca/highlights/openreply)). Many forks come from non-developer businesses such as fitness coaches and marketing shops, which fits the pattern of creators deploying it after seeing the reel ([example fork](https://github.com/Keatonmac-Fitness/openreply)). OpenReply has no Claude code. Its README does include a ready-made prompt so that "Claude Code, Cursor, or a similar tool" can walk you through setup ([OpenReply README](https://github.com/diwenne/openreply)).

Two other kinds of viral content could be what you remember, and one of them is a trap. Several popular "Claude + Instagram DM" posts still run on ManyChat. Sabrina Ramonov's TikTok uses Claude to *build* ManyChat automations ([TikTok](https://www.tiktok.com/@sabrina_ramonov/video/7618606049490111758)), and a widely shared Threads post describes ManyChat's own Claude integration ([Threads @kotovdeny](https://www.threads.com/@kotovdeny/post/DWOiwm7jTGk/claude-has-legitimately-just-changed-instagram-d-ms-forever-you-can-now-connect)). There is also an Instagram reel titled "I just replaced ManyChat with Claude Code." Its creator and the repo it links to could not be identified ([Instagram reel](https://www.instagram.com/reel/DW4fIz3D1NB/)).

The rest of the field is far smaller. Star counts are a snapshot from 2026-09-27, and they reward marketing more than code quality. For example, insta-p8 has several near-identical copies under other accounts that look like SEO amplification ([insta-p8](https://github.com/ayuuxh2/insta-p8)).

## Every credible clone uses one Meta endpoint with hard limits

Nearly every "free ManyChat" repo works the same way. A `comments` webhook fires, the code checks for a keyword, and it calls `POST /<IG_ID>/messages` with `recipient: {comment_id}`. That call is Meta's **Private Replies** API. Meta's rules are strict. The reply must go out **within 7 days** of the comment. **Only one message** can be sent to the commenter. Follow-ups are allowed only after the person responds, and only within a 24-hour window ([Meta: Private Replies](https://developers.facebook.com/docs/instagram-platform/private-replies)). Code inspection confirmed this call in OpenReply, ChatbotX, insta-p8, chatmany and about 15 other repos ([OpenReply client.ts](https://github.com/diwenne/openreply/blob/HEAD/lib/meta/client.ts), [ChatbotX comment.ts](https://github.com/ChatbotXIO/ChatbotX/blob/HEAD/integrations/instagram-facebook/src/apis/comment.ts)). Two notable projects appear not to use it. slidein DMs the commenter's user ID directly ([slidein webhook handler](https://github.com/molt-oss/slidein/blob/HEAD/apps/worker/src/handlers/webhook-handler.ts)), and IG Harness sends plain DMs and @mention comments ([IG Harness](https://github.com/Shudesu/ig-harness-oss)). Those DMs probably fail for commenters who have no open message thread, though this has not been tested.

The day-to-day friction comes from Meta's side. OpenReply's author found that "**webhooks frequently drop comments**," so OpenReply re-checks 72 hours of post history on a schedule ([diwen.ca](https://www.diwen.ca/highlights/openreply)). CharanMN7's worker adds a 5-minute poll for the same reason ([ig-comment-dm](https://github.com/CharanMN7/ig-comment-dm)). Duplicate webhook deliveries also happen. The n8n community recommends deduplicating on user + post + campaign, with a 120-second cooldown ([n8n community](https://community.n8n.io/t/i-built-a-self-hosted-instagram-comment-to-dm-system-with-n8n/303886)). DMs to non-followers land in Message Requests, where "a URL in the message text isn't tappable." Put links in buttons, which Meta caps at 20 characters. Comments on your own posts from your own account don't trigger anything ([free-claude-autodm-kit](https://github.com/Mahanaicoach/free-claude-autodm-kit), [publik chatmany page](https://publikhq.com/chatmany)). There is no webhook for new followers, so welcome-DMs-on-follow are impossible ([nudgra-oss](https://github.com/MaikoCode/nudgra-oss)). The follow gate relies on `is_user_follow_business` and lets people through when Instagram doesn't return a follow status ([OpenReply README](https://github.com/diwenne/openreply)). OpenReply's open issues follow the same themes: an empty comments endpoint (#64) and duplicate replies from polling races (#69) ([OpenReply issues](https://github.com/diwenne/openreply/issues?q=is%3Aissue)).

These rules decide where Claude belongs. The first DM is a single message, so it works best as a fixed template: link, button, maybe the person's name. An AI agent has little to add there. **Claude earns its keep once the fan replies.** From then on the 24-hour window allows real conversation: answering questions, qualifying a lead, collecting an email, or handing off to you. Meta's cap also prevents a bot from chasing people who never answered.

## Your own account needs a Live app, not App Review

Meta's rule on access levels is short. Standard Access is the default. Advanced Access, which requires App Review and Business Verification, is needed when "your app serves Instagram professional accounts that you don't own or manage" ([Meta: Instagram Platform overview](https://developers.facebook.com/docs/instagram-platform/overview)). OpenReply's setup guide applies that rule directly. A published app holds Standard Access to `instagram_business_basic`, `instagram_business_manage_comments` and `instagram_business_manage_messages`, which "covers Instagram accounts that have a role on your app." The guide concludes that this "is enough to run OpenReply for your own accounts… No App Review needed" ([OpenReply setup.md](https://github.com/diwenne/openreply/blob/main/docs/setup.md)). poststack's documentation reaches the same conclusion, adding that "Live mode ≠ Advanced Access" ([poststack README](https://github.com/jurczykpawel/poststack#meta-access-levels--what-needs-app-review-and-what-doesnt)). So does IG Harness, which says DM delivery works "on Standard Access (no Meta App Review required) for Pro accounts you own" ([IG Harness README.en](https://github.com/Shudesu/ig-harness-oss/blob/main/README.en.md)). juancadile/instabot is more cautious and says the same thing "to the best of our understanding" ([instabot](https://github.com/juancadile/instabot)).

**How confident is this?** It is high but not certain. The research relied on Meta's platform overview and developer documentation, not on Meta's App Review requirements page, and some sources point the other way. Botpress's guide for bring-your-own-app setups says a bot "will work for admins, developers, and testers of the app only" until review is approved ([Botpress docs](https://botpress.com/docs/integrations/integration-guides/instagram/)). Chatwoot's self-hosted guide says the app must be "verified by Facebook" before production ([Chatwoot docs](https://developers.chatwoot.com/self-hosted/configuration/features/integrations/instagram-channel-setup)). jlbadano/ig-mcp says its DM tools "require Advanced Access" ([ig-mcp](https://github.com/jlbadano/ig-mcp)). One research thread concluded from the Botpress wording that App Review is effectively mandatory. There is a plausible explanation for the conflict. Botpress, Chatwoot and generic MCP tools are built to serve *other people's* accounts, which is exactly Meta's Advanced Access case. The "testers only" behavior also matches an app still in Development mode. That explanation is a reasonable inference, not a confirmed fact. OpenReply's own launch (a reel drawing 8,801 comments, with DMs sent by OpenReply) shows the code can DM the public at scale, but the sources don't say what access level the author's app had. The test is cheap. After publishing the app, comment your keyword from a second Instagram account that has no role on the app. If the DM arrives, you're confirmed. If it doesn't, your options are App Review, a connection provider such as Zernio, or a hosted tool.

What setup is actually required: an Instagram **Professional (Business or Creator)** account, a Meta developer app using "Instagram API with Instagram Login" (no Facebook Page needed; the Facebook Login path does need a linked Page), a public HTTPS URL for webhooks, and a second Instagram account for testing ([Meta overview](https://developers.facebook.com/docs/instagram-platform/overview), [chatmany](https://github.com/ryanlaiyanip-ctrl/chatmany)). chatmany estimates **about 45 minutes**. Ignore any tutorial or repo built on the Instagram Basic Display API, which Meta shut down in December 2024 ([TechCrunch](https://techcrunch.com/2024/12/06/instagram-locks-out-developers-of-third-party-consumer-apps)). Most failed installs trace back to a handful of traps:

| Trap | Symptom | Fix |
|---|---|---|
| App left in Development mode | Only the console "Test" button delivers events. Instagram returns empty comment and message lists with no error | Publish the app (Live) ([OpenReply setup.md](https://github.com/diwenne/openreply/blob/main/docs/setup.md), [chatmany](https://github.com/ryanlaiyanip-ctrl/chatmany)) |
| Your own account has no role on the app | "Insufficient Developer Role" error | Add yourself as an Instagram tester and accept the invite. "Even your own account has to be added and accept" ([OpenReply setup.md](https://github.com/diwenne/openreply/blob/main/docs/setup.md)) |
| Tester invite opened on a phone | Invite cannot be accepted | Accept it from a desktop browser ([chatmany](https://github.com/ryanlaiyanip-ctrl/chatmany)) |
| Wrong credentials | Auth fails; a Meta app has **two** app ID/secret pairs | Use the Instagram app ID/secret under "API setup with Instagram login" ([chatmany](https://github.com/ryanlaiyanip-ctrl/chatmany)) |
| Dashboard "Generate token" button | Automation stops within hours | Use the repo's OAuth flow; that token "expires in hours" ([chatmany](https://github.com/ryanlaiyanip-ctrl/chatmany)) |

App Review becomes unavoidable only if you run this for clients. The repos agree that serving accounts you don't own requires Advanced Access, App Review and Business Verification ([brightbean-chat Instagram docs](https://github.com/brightbeanxyz/brightbean-chat/blob/HEAD/docs/channels/instagram.md)). That paperwork is the service that Zernio, Upload-Post and Blotato sell.

## Four concrete paths, from a $0 fork to a full flow builder

| Path | What you get | How Claude plugs in | Running cost | Main trade-off |
|---|---|---|---|---|
| **A. Fork OpenReply, add Claude (or deploy openinstadm)** *(recommended)* | Keyword → DM, public reply, follow gate, Story-reply triggers, inbox, tracked links | Anthropic SDK step in the DM webhook handler; openinstadm's `lib/ai/` module is a ready reference | ~$0 on Vercel/Neon/Redis Cloud/Oracle free tiers, plus Claude usage | You run a Next.js app plus an always-on Redis worker |
| **B. Self-hosted n8n + templates** | Visual workflows; Instagram, Messenger and WhatsApp in one place | Native Anthropic Chat Model node | Community Edition free plus your server; Cloud from €20/mo | You assemble it; no template pairs Instagram with Claude |
| **C. ChatbotX self-hosted** | Flow builder with 15+ node types, inbox with human takeover, CRM, broadcasts, sequences | Built in (`@ai-sdk/anthropic`) | Free Community Edition plus a server for the Docker stack | Young project, heavy stack, license carve-out, cloud upsell |
| **D. Zernio-based Claude kit** | Comment → DM without creating a Meta app | `claude` CLI drafts and triages | Zernio free for 2 accounts | A third party holds your Instagram connection |

**Path A is the best balance for a creator who wants Claude.** OpenReply is by far the most-used codebase and is actively maintained (last push 2026-09-21). It suggests free-tier hosting for every part: Vercel, Neon Postgres, Redis Cloud, and an Oracle Cloud always-free VM for the worker ([OpenReply README](https://github.com/diwenne/openreply)). Adding Claude to it is moderate work. You need a new step in the `messages` webhook handler, somewhere to store conversation history, a check that the 24-hour window is still open, and a flag that lets a human take over. openinstadm, which shares OpenReply's upstream (im-anishraj's CampaignCue), already does most of this. It imports `createAnthropic` from `@ai-sdk/anthropic`, offers `claude-haiku-4-5` and `claude-sonnet-4-6`, and grounds replies in a "knowledge textbox" ([openinstadm client.ts](https://github.com/Xeven777/openinstadm/blob/HEAD/lib/ai/client.ts)). You can deploy openinstadm directly and accept a 10-star fork, or port its AI module into a fresh OpenReply fork and keep the larger community. The second option is safer. DeltaplaneX's small bot has a handoff pattern worth copying: Claude Sonnet writes replies, Haiku extracts facts for memory, and an `ESCALATE` signal pauses the bot so a human takes over ([DeltaplaneX](https://github.com/DeltaplaneX/instagram-dm-bot)). Call Claude through Anthropic's native SDK, not an "OpenAI-compatible" shim. Anthropic says its compatibility layer "is not considered a long-term or production-ready solution" and does not support prompt caching ([Claude docs: OpenAI SDK compatibility](https://platform.claude.com/docs/en/api/openai-sdk)). The same advice applies if you adapt insta-p8, whose AI fallback lives in one OpenAI-style module ([insta-p8 ai-reply.ts](https://github.com/ayuuxh2/insta-p8/blob/HEAD/lib/ai-reply.ts)). If you would rather avoid a Redis worker, chatmany runs on Cloudflare's free tier at "$0/month at single-creator scale" but has no AI ([chatmany](https://github.com/ryanlaiyanip-ctrl/chatmany)).

**Claude itself costs little at creator volumes.** Claude Haiku 4.5 is priced at $1 per million input tokens and $5 per million output tokens. Sonnet 5 is $2 and $10 ([Claude pricing](https://platform.claude.com/docs/en/about-claude/pricing)). Assume each reply sends about 2,000 tokens of prompt, FAQ and history and gets back about 200 tokens. That works out to roughly **$3 per 1,000 AI replies on Haiku** and about $6 on Sonnet 5. This estimate is my own arithmetic; the ig-setter author claims about $0.001 per DM ([ig-setter](https://github.com/brodyautomates/ig-setter)). Keyword-to-DM sends need no model at all.

**Path B suits you if you already think in workflows or want WhatsApp too.** n8n's Facebook Trigger can subscribe to Instagram `comments` and `messages` events. n8n also has native WhatsApp Business Cloud nodes and a native Anthropic Chat Model node ([n8n Facebook Trigger docs](https://docs.n8n.io/integrations/builtin/trigger-nodes/n8n-nodes-base.facebooktrigger/instagram), [n8n Anthropic Chat Model](https://docs.n8n.io/integrations/builtin/cluster-nodes/sub-nodes/n8n-nodes-langchain.lmchatanthropic)). Sending a DM still means an HTTP Request node calling the Graph API. The Instagram trigger has a reported bug where messages don't arrive, so many templates use a plain Webhook node instead ([n8n issue #12456](https://github.com/n8n-io/n8n/issues/12456)). A practical build combines three templates. Template #15206 handles keyword comment → DM and avoids infinite loops ([n8n #15206](https://n8n.io/workflows/15206-send-instagram-auto-dms-to-post-commenters-using-meta-graph-api/)). Template #16300 adds the webhook verification handshake and public replies ([n8n #16300](https://n8n.io/workflows/16300-reply-to-instagram-and-facebook-comments-via-meta-webhooks-and-dms/)). Template #14026, an AI DM agent with memory, explicitly says to "Swap the Google Gemini Chat Model sub-node for any other supported LLM (OpenAI, Anthropic, etc.)" ([n8n #14026](https://n8n.io/workflows/14026-auto-reply-to-instagram-dms-with-an-ai-chatbot-and-google-gemini-history/)). Self-hosting the Community Edition is free under the Sustainable Use License, which permits "your own internal business purposes" but not reselling ([n8n LICENSE](https://github.com/n8n-io/n8n/blob/master/LICENSE.md)). n8n Cloud Starter costs €20/mo (billed annually) for 2,500 executions ([n8n pricing](https://n8n.io/pricing/)), and one viral post could use that up. If you add WhatsApp, note that Meta's Business API terms have banned **general-purpose** AI chatbots since 2026-01-15. Bots scoped to your business, such as support, bookings or sales, remain allowed ([TechCrunch](https://techcrunch.com/2025/10/18/whatssapp-changes-its-terms-to-bar-general-purpose-chatbots-from-its-platform)).

**Path C is for someone who wants ManyChat's full builder, not only comment-to-DM.** ChatbotX's private-reply call and Anthropic SDK dependency are confirmed in the code ([ChatbotX package.json](https://github.com/ChatbotXIO/ChatbotX/blob/HEAD/packages/ai/package.json)). But the project leads with a paid cloud trial, keeps an enterprise folder under a commercial license, has 87 open issues, and needs Postgres/pgvector, Redis and more in Docker ([ChatbotX](https://github.com/ChatbotXIO/ChatbotX)). The self-hosted community plan is free; white-label costs $299/mo ([OpenAlternative](https://openalternative.co/chatbotx)). Run a hands-on proof of concept before committing. **Path D** skips Meta app setup entirely. You drop free-claude-autodm-kit into Claude Code and it builds on Zernio, which "gives you 2 connected accounts free, permanently" ([free-claude-autodm-kit](https://github.com/Mahanaicoach/free-claude-autodm-kit)). You trade the Meta setup for dependence on a vendor.

Two familiar tools don't fit. Chatwoot ignores Instagram comment webhooks ([Chatwoot PR #15596](https://github.com/chatwoot/chatwoot/pull/15596)), and Botpress is no longer self-hostable ([Botpress v12 sunset](https://botpress.com/docs/studio/guides/advanced/v12/)). Zapier's Instagram app has only media triggers ([Zapier](https://zapier.com/apps/instagram-for-business/integrations)). There is also a non-DIY fallback. Hosted tools such as InstantDM ($9.99/mo), CreatorFlow ($15) and LinkDM ($19) include comment-to-DM for less than ManyChat. None was found that accepts your own Claude key, and those prices come from InstantDM's own comparison page ([InstantDM comparison](https://instantdm.com/best-instagram-dm-automation-tools)).

## Password-login tools trade a $30 bill for your account

A second group of "Claude + Instagram DM" projects skips Meta's API. They log in with your **username and password** and drive Instagram's private mobile API, usually through the Python library **instagrapi** (6,856 stars). The most-starred Instagram DM MCP server, **trypeggy/instagram_dm_mcp** (183 stars), stores your Instagram password in `.env` or in `claude_desktop_config.json`. It pins an old instagrapi 2.1.5, was last updated in August 2025, and has **no comment monitoring at all**. A pull request to add rate limiting "to protect accounts from anti-abuse bans" is still unmerged ([instagram_dm_mcp](https://github.com/trypeggy/instagram_dm_mcp), [PR #12](https://github.com/trypeggy/instagram_dm_mcp/pull/12)). Stupidoodle/instagram-mcp says it was "built entirely by Claude (Opus 4.5) in ~3 hours with mass auto-accept enabled." It ships a `/dm` skill that runs conversations "for hours/days," and its README tells a story of the agent pressing on after the other person wrote "give up" ([instagram-mcp](https://github.com/Stupidoodle/instagram-mcp)). These tools don't give you ManyChat's comment-to-DM feature. What they offer is DM access on a personal account, at real risk.

The risk is well documented. instagrapi's own README warns that "private API automation is fragile in production." For "account-owned business workflows," it says to "prefer official Instagram APIs" ([instagrapi](https://github.com/subzeroid/instagrapi)). Its 2026 issue tracker shows the pattern. A September issue reports logins failing with "Your version of Instagram is out of date" ([#2807](https://github.com/subzeroid/instagrapi/issues/2807)). A July pull request adds an `AccountSuspended` exception for challenges that point to `/suspended/`, which it calls "a terminal account-state response" ([PR #2737](https://github.com/subzeroid/instagrapi/pull/2737)). A maintainer tracking issue notes that users "regularly hit `429`, `feedback_required`, signup blocks" ([#2423](https://github.com/subzeroid/instagrapi/issues/2423)). Instagram's Terms bar collecting information "in an automated way without our express permission" ([Instagram Terms](https://help.instagram.com/581066165581870/)). Meta has sued automation vendors that mimicked the official app, including MGP25 in 2020 ([Social Media Today](https://www.socialmediatoday.com/news/facebook-launches-new-legal-action-against-fake-engagement-sellers-and-data/580135/)) and Voyager Labs in 2023 ([CNBC](https://www.cnbc.com/2023/01/12/meta-sues-voyager-labs-over-scraping-user-data.html)). For an individual, the realistic risk is losing the account, not a lawsuit. On WhatsApp the signal is even stronger. One whatsapp-web.js user was **banned after about three messages** despite following every recommended precaution ([wwebjs #4008](https://github.com/wwebjs/whatsapp-web.js/issues/4008)). The popular whatsapp-mcp README itself warns that prompt injection "could lead to private data exfiltration" ([whatsapp-mcp](https://github.com/lharries/whatsapp-mcp)). The only situation where the unofficial route is the sole option is a personal, non-professional Instagram account, because the official API doesn't support those. The simpler fix is to convert to a Creator or Business account, not to hand Claude your password.

## Conclusion

For a single creator, ManyChat's biggest advantage has not been its software. It has been Meta's approval and managed hosting. If the Standard Access reading holds, and the evidence strongly suggests it does, the approval barrier disappears for your own account. Paying ManyChat then mostly buys maintenance: recovering dropped webhooks, refreshing tokens, deduplicating replies and handling rate limits. OpenReply's issue tracker shows these are the real ongoing costs of going DIY, not the $0–5 hosting bill. Meta's one-message rule also sets the AI design for you. The keyword trigger should stay a dumb, reliable template, and Claude's job starts when a fan writes back. That limit also rules out the runaway-agent behavior the password-login tools allow.

The calculation changes as soon as you want to run this for other people's accounts. Serving clients brings back App Review and Business Verification, n8n's license forbids reselling, and Meta's legal enforcement has targeted vendors rather than individuals. Start with your own account on an OpenReply fork plus a Claude step, confirm with the second-account test, and treat a client-facing service as a separate project.
