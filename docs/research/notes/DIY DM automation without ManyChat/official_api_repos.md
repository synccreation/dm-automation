Method note (applies to every section): candidates were found with GitHub REST search (queries: "comment to dm instagram", "manychat alternative", "manychat clone", "private replies instagram", "instagram messaging api", "instagram dm claude", "instagram anthropic", "instagram comment automation", "instagram dm ai agent", "instagram chatbot webhook", "user:fbsamples", "whatsapp cloud api chatbot", "instagram dm automation", "messenger platform bot", "topic:instagram-automation", "instagram claude bot"), run on 2026-09-27. About 45 repos were then shallow-cloned and checked with `git grep` for `recipient: { comment_id }`, Graph hosts (`graph.instagram.com` vs `graph.facebook.com`), webhook fields, story handling, and LLM SDK imports. Star counts are from the GitHub API on 2026-09-27 and are approximate. "Last commit" is the HEAD commit date of the clone. Unless noted, the source for each repo fact is the repo URL or the file path linked. `gh` CLI was not installed, so I used the unauthenticated REST API and could not run GitHub code search, which needs auth.

## Q1. Which repos implement Instagram comment-to-DM via the official private-replies endpoint (POST /{ig-id}/messages with recipient.comment_id) plus `comments` + `messages` webhooks?

### Takeaway
At least 20 actively maintained (2026) open-source repos send real Instagram private replies with `recipient: { comment_id }`, verified in code. Most call `graph.instagram.com`, the Instagram API with Instagram Login. The strongest are diwenne/openreply (about 2.5k stars), ChatbotXIO/ChatbotX (about 840), ayuuxh2/insta-p8 (about 140), brightbeanxyz/brightbean-chat, jurczykpawel/poststack, ryanlaiyanip-ctrl/chatmany, and several Cloudflare-Worker single-tenant bots. A few popular repos (IG Harness, slidein) do not appear to use `comment_id` at all. zernflow and the Claude "autodm kits" route through paid third-party aggregators such as Zernio or Blotato, not Meta directly.

### Cited Findings
**Meta's rules for the endpoint (primary source):**
- A private reply is `POST <HOST>/<API_VERSION>/<IG_ID>/messages` with a `recipient` object containing `comment_id`. It works with both Instagram Login and Facebook Login. Required permissions are `instagram_business_basic` + `instagram_business_manage_comments` with IG Login, or `instagram_basic`, `instagram_manage_comments`, `pages_read_engagement` with FB Login. The message must be sent within 7 days of the comment. Only one message can go to the commenter, and follow-ups are allowed only if the person responds, within 24h. Live-comment private replies work only during the broadcast. — [Meta: Private Replies](https://developers.facebook.com/docs/instagram-platform/private-replies)
- Rate limits are 750 calls/hour per IG professional account for private replies to post/reel comments, and 100 calls/sec for Live-comment private replies. The Send API allows 100 calls/sec for text/links/reactions/stickers. — [Meta: Instagram Platform overview](https://developers.facebook.com/docs/instagram-platform/overview)
- Hosts: Instagram Login uses `graph.instagram.com` with an Instagram User token. Facebook Login uses `graph.facebook.com` with a Facebook User or Page token and needs a linked Page. — [Meta: Instagram Platform overview](https://developers.facebook.com/docs/instagram-platform/overview)

### Inferences
- The openreply lineage (im-anishraj → openreply → openinstadm / nudge1 / ChatFlow) is the most-copied comment-to-DM codebase on GitHub in 2026. They share the same Next.js + Prisma + BullMQ/Redis worker architecture and `lib/meta/client.ts`.
- Per Meta's docs, a private reply is the sanctioned way to open a DM from a comment. Repos that DM `comment.from.id` directly (slidein, and apparently IG Harness) likely fail for commenters who have no open 24h messaging window. This is not tested; verify before relying on them.
- Several repos (chatmany, CharanMN7, aldoprianandi) add comment polling as a safety net for missed webhooks. That is a practical detail worth copying.

### Gaps
- GitHub code search (auth-only) was not available, so repos that implement private replies without matching keywords in their name or description may be missed.
- I verified by static grep, not by running the code. I did not confirm that any repo works end to end against a live account.
- BlondelSeumo/Social-Media-Marketing-Platform (36 stars, PHP, last push 2022-02-07) returned an essentially empty README (14 bytes) and was not cloned. Its API path is unverified and it predates the 2024 IG Login API.

## Q2. Which repos are full "ManyChat clones" (flow builder, keyword rules, contact DB, broadcast) vs. minimal webhook bots? (Master catalog)

### Takeaway
Only about four repos are real ManyChat-class platforms on the official APIs, with a visual flow builder, CRM, broadcasts/sequences, and multi-channel support: **ChatbotX**, **brightbean-chat**, **zernflow** (aggregator-based), and, to a lesser extent, **poststack** and **IG Harness**. The large majority (openreply and its forks, chatmany, CharanMN7, aldoprianandi, AutoDMX, oh-daddy, less-chat) are deliberately narrow comment-to-DM campaign tools. They add keyword rules, public reply, follow gate, link tracking, and a small dashboard, but no flow builder.

### Inferences
- For a "ManyChat clone with AI", ChatbotX is the most complete base with Claude already supported. Mind the enterprise-directory commercial carve-out and its hosted-cloud upsell. brightbean-chat is the cleanest official-API-only multi-channel base but deliberately has no AI, and its AGPL applies to network use.
- For a lean Claude-powered comment-to-DM build, the best starting points are openreply or its fork openinstadm (openinstadm already has `@ai-sdk/anthropic`), insta-p8 (AI fallback with story triggers), and slidein (native Anthropic calls on Workers). slidein should first be fixed to use `recipient.comment_id`.
- Star counts are skewed by marketing. openreply's 2.4k stars came within months, and several READMEs contain SEO keyword blocks. Code depth matters more than stars.

### Gaps
- I did not compare flow-engine semantics (branching and waits) between ChatbotX, brightbean, and zernflow beyond README node lists.
- Contributor counts and issue activity were not collected because of rate limits.

### Takeaway
Claude is already wired into ChatbotX, openinstadm, slidein, and zernflow. ## Q5. What setup does each require (Meta app, App Review, Business Verification, hosting)?

### Takeaway
For your **own** Instagram professional account, all of these repos run on Meta's default **Standard Access**, with no App Review and no Business Verification. The app must still be switched to **Live/Published** mode for real webhooks, and test accounts must accept tester invites. **Advanced Access, which requires App Review plus Business Verification, is needed only to serve accounts you don't own or manage** (agency or SaaS use). Hosting splits into Cloudflare Workers + D1 ($0 tier), Vercel + Supabase/Neon, Next.js + Postgres + Redis with an always-on worker, or Docker Compose on a VPS.

### Cited Findings
- **Meta's rule:** Standard Access is the default. Advanced Access is required when "your app serves Instagram professional accounts that you don't own or manage" and requires App Review and Business Verification. — [Meta: Instagram Platform overview](https://developers.facebook.com/docs/instagram-platform/overview)
- poststack's README has the clearest write-up. For your own Pages and IG accounts you do "not need Meta App Review or Business Verification". The app must be in **Live** mode to receive real webhooks ("In Development mode Meta delivers only test webhooks… Live mode ≠ Advanced Access"). App Review applies once you handle accounts whose owners are not Testers on your app. — [poststack README](https://github.com/jurczykpawel/poststack#meta-access-levels--what-needs-app-review-and-what-doesnt)
- chatmany lists the common setup failures. There are two different app ID/secret pairs; use the "Instagram app ID/secret" under "API setup with Instagram login". Don't use the dashboard "Generate token" button because that token "expires in hours". The redirect URL must be registered in two places. The app "MUST be Published… If it isn't, Instagram returns empty comment and message lists with no error". Node 22+ is required, and the tester invite must be accepted from a desktop browser. A second IG account is needed to test. Setup takes about 45 minutes and runs on Cloudflare's free tier. — [chatmany README](https://github.com/ryanlaiyanip-ctrl/chatmany)
- nudgra-oss: "Your Meta app must be published for webhooks to work, and each Instagram account must accept its tester invite." It deploys to a VPS with Docker Compose + Caddy. — [nudgra-oss](https://github.com/MaikoCode/nudgra-oss)
- IG Harness: "Meta 審査 不要（Standard Access で動作）" (Meta review not required; runs on Standard Access). Advanced Access is needed only for true nested thread replies and for multi-tenant hosting of accounts you don't own. It sets up with `npx create-ig-harness` on Cloudflare (Workers, D1, R2, Pages). — [IG Harness README](https://github.com/Shudesu/ig-harness-oss)
- brightbean-chat: "Running this yourself means creating your own Meta developer app, passing app review for the permissions each channel needs". Its `docs/channels/instagram.md` requires "Advanced Access, App Review and Business Verification" to serve others' accounts. It deploys with Docker Compose or one-click Railway. — [brightbean-chat](https://github.com/brightbeanxyz/brightbean-chat), [docs/channels/instagram.md](https://github.com/brightbeanxyz/brightbean-chat/blob/HEAD/docs/channels/instagram.md)
- openreply needs "your deployed fork, a public HTTPS URL, PostgreSQL, Redis, a running worker, and an Instagram connection". Its docs name Vercel, Neon, Redis Cloud, an Oracle Cloud always-free VM for the worker, and Resend. — [openreply](https://github.com/diwenne/openreply)
- Hosting by repo (from READMEs):
  - Cloudflare Workers/D1: chatmany, CharanMN7 ("$0/month"), aldoprianandi (+Queues), IG Harness (+R2/Pages), slidein.
  - Vercel + Supabase: insta-p8, zernflow, open-autodm. AutoDMX uses Supabase + GitHub Actions cron.
  - Vercel + Neon: less-chat.
  - Railway: oh-daddy (Postgres + Inngest), juancadile/instabot, brightbean one-click, whatsapp-agentkit.
  - Docker Compose: ChatbotX (plus a separate [chatbotx-docker-compose](https://github.com/ChatbotXIO/chatbotx-docker-compose) repo), brightbean, poststack.
  - Supabase Edge Functions: DeltaplaneX. n8n + Vercel + Supabase: ig-setter.
- Account-type prerequisites: IG Login automation needs an Instagram **Professional** (Business/Creator) account ([chatmany](https://github.com/ryanlaiyanip-ctrl/chatmany), [less-chat](https://github.com/less-chat/less-chat)). The FB Login path additionally needs a linked Facebook Page ([Meta overview](https://developers.facebook.com/docs/instagram-platform/overview)). WhatsApp needs a WhatsApp Business Account, and outside the 24h window only approved templates are allowed ([brightbean channel table](https://github.com/brightbeanxyz/brightbean-chat), [zernflow](https://github.com/zernio-dev/zernflow)).
- Webhook `messages` subscriptions deliver story replies as DMs, which is how openreply implements "Reply LINK to this Story" triggers. — [openreply](https://github.com/diwenne/openreply)
- nudgra-oss says new-follower welcome DMs are impossible because Instagram exposes no follower webhook. — [nudgra-oss](https://github.com/MaikoCode/nudgra-oss)

### Inferences
- A solo creator automating their own account can skip App Review and Business Verification entirely. Budget about 45–60 minutes of Meta dashboard setup (per chatmany and less-chat) and make sure the app is Live. Serving clients' accounts turns this into an App Review and Business Verification project, which is exactly what the aggregator options (Zernio, Blotato, Upload-Post) sell around.
- Using AI replies to DMs adds no extra Meta permission beyond `instagram_business_manage_messages`. However, the 24h messaging window still limits when Claude-generated follow-ups can be sent. This is inferred from Meta's private-reply rule that follow-ups require a response within 24h.

### Gaps
- I did not fetch Meta's App Review requirements page itself, including the screencast requirements and the exact permission list per use case. The Standard/Advanced split is sourced to the Instagram Platform overview and repo docs only.
- I did not independently verify whether Business Verification is required for the WhatsApp Cloud API at small volumes; that is left to the WhatsApp-focused researcher.
